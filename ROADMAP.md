# Roadmap

## Phase 1: foundation

Status: complete

Create repository contracts, publication rules, structure, attribution, and automated documentation checks.

Exit criteria:

- Core contract files exist.
- Public-safety and link checks run locally.
- The approved screenshot is tracked with context.

## Phase 2: workflow and knowledge base

Status: complete

Document the main flow, project lifecycle, agent-writing rules, Obsidian knowledge boundary, and cross-machine continuity.

Exit criteria:

- The workflow names inputs, outputs, owners, gates, and evidence.
- Obsidian guidance separates private knowledge from public and repository state.

## Phase 3: tools, coordination, and design

Status: complete

Document Pi, Herdr, model routing, bounded parallelism, handoffs, and frontend design work.

Exit criteria:

- Coordination examples enforce one writer per file or worktree.
- Model selection is proportional to task complexity.
- Design work requires rendered and accessibility evidence.

## Phase 4: templates, skills, and examples

Status: complete

Publish original reusable materials and fictional worked examples.

Exit criteria:

- A reader can apply the workflow without access to the author's private environment.
- Third-party material is linked and attributed rather than silently copied.

## Phase 5: publication readiness

Status: complete

Run all checks, privacy review, link review, and independent fresh-context review. Prepare the GitHub repository without merging or publishing until the human approves the final diff.
